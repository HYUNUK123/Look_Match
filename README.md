## 2. 문제 정의 — 무엇이 진짜 어려운가

범용 의미 검색 모델(SigLIP2/CLIP)은 **색상 등 전체적 유사성은 이미 잘 찾습니다.** 그래서 "되는 것"이 아니라, 그럼에도 **안 되는 세부 속성**을 문제로 정의했습니다.

검색어 **"베이지 와이드 슬랙스"** 를 예로 들면:

| 속성 | 결과 | 원인 |
|---|---|---|
| 베이지 (색상) | ✅ 잘 맞음 | — |
| 와이드 (핏) | ❌ 스트레이트와 혼동 | **사진 자체가 모호** (각도·연출) |
| 슬랙스 (종류) | ❌ 치노/코튼팬츠와 혼동 | **캡션 생성 모델도 구분 못 해 학습 라벨이 부정확** |

→ 두 문제 모두 **이미지 신호만으로는 풀기 어렵다**는 공통점이 있습니다.

## 3. 전체 아키텍처

**데이터 파이프라인 (오프라인)**
```
네이버쇼핑 API (약 96K) → YOLO 크롭 + 512×512 패딩 → Qwen3-VL 캡션 생성
   → 약 71K 이미지·텍스트 쌍 → SigLIP2 LoRA 파인튜닝 → Qdrant 인덱싱
```

**추론 파이프라인 (검색)**
```
User(Text/Image) → SigLIP2 임베딩 → Qdrant 벡터 검색(Top-20)
   → BGE Reranker(텍스트 재정렬) → Final Results → GPT-4o/Qwen 추천 이유
```

- **1차(Retrieve)**: 이미지 임베딩으로 빠르게 후보 20개 확보 (recall)
- **2차(Rerank)**: 검색어 ↔ 상품명 텍스트 관련도로 정밀 재정렬 (precision)

## 4. 데이터 구축

### 4-1. 수집 — 네이버쇼핑 API
- 상의/하의/아우터/원피스·세트 등 **131개 키워드**로 약 **96K 상품** 수집 (이미지·상품명·가격·URL)
- 키워드당 호출 한도·페이지네이션 처리, 중단 시 이어받기 로직으로 안정적 대량 수집

### 4-2. 이미지 정제 — YOLO 크롭 + 패딩
- 네이버 상품 사진은 상의·하의·모델·배경이 함께 있어 **특정 부위 학습에 방해** → YOLO로 대상 의류만 크롭
- 크롭 후 **종횡비를 유지한 채 512×512로 패딩(레터박스)** → 이미지 왜곡 없이 입력 규격 통일

### 4-3. 텍스트 정제 — Qwen3-VL 캡션 생성
- 네이버 상품명은 키워드 나열·SEO 문구·브랜드/상품번호가 섞여 학습에 부적합
- **Qwen3-VL-8B (4bit 양자화)** 로 `색상·종류·핏·패턴·디테일` 5필드 구조화 캡션을 자동 생성
- **프롬프트 엔지니어링**으로 노이즈 제거:
  - 영어로 지시 + 한국어로만 출력 (한자·외국어 혼입 방지)
  - 색상 옵션이 나열된 사진(옵션컷)은 별도 판별 스텝으로 필터
  - 추상어·브랜드명 금지, 예시문 복사 방지

> **문제의식**: 검색 성능은 모델만이 아니라 **검색 데이터의 품질**에 크게 좌우된다 → 데이터 정제에 집중.

## 5. 모델 선정 & 파인튜닝

### 5-1. 모델 선정 — Jina CLIP v2 vs SigLIP2
한국어가 가능한 두 모델을 **같은 데이터로 각각 파인튜닝 후 Recall 비교** (텍스트→이미지, 검증셋 10% ≈ 7,100쌍):

| 모델 | R@1 | R@5 | R@10 |
|---|---|---|---|
| Jina CLIP v2 (원본) | 0.096 | 0.249 | 0.349 |
| Jina CLIP v2 (파인튜닝) | 0.214 | 0.492 | 0.630 |
| SigLIP2 (원본) | 0.108 | 0.256 | 0.351 |
| **SigLIP2 (파인튜닝) ★채택** | **0.285** | **0.585** | **0.723** |

- **채택 이유 ①**: 파인튜닝 후 모든 Recall 지표에서 SigLIP2 우세 (R@5 58.5% vs Jina 49.2%)
- **채택 이유 ②**: Jina CLIP v2는 상업용 라이선스가 없어 실무 활용 불가 → **상업 활용 가능한 SigLIP2** 채택

### 5-2. 파인튜닝 구조 & 실험
- (이미지, 캡션) 쌍의 대조학습(contrastive)으로 한국 패션 도메인에 적응
- **Text Encoder 학습 여부 실험**: freeze(R@5 54.9%) vs full 파인튜닝(R@5 58.5%) → **full 채택**

**SigLIP2 파인튜닝 효과 (Before → After, 텍스트→이미지)**

| 지표 | 파인튜닝 전 | 파인튜닝 후 |
|---|---|---|
| R@1 | 0.108 | **0.285** |
| R@5 | 0.256 | **0.585** |
| R@10 | 0.351 | **0.723** |

## 6. 2단계 검색 — 문제 해결 과정

### 6-1. 문제 발견
파인튜닝 후에도 "베이지 와이드 슬랙스" 검색 시 **스트레이트 핏·치노팬츠가 상위에 섞임** (색상은 맞지만 핏·종류 구분 실패).

### 6-2. 1차 시도 — VLM 리랭킹 (실패)
- Top-20을 Qwen/GPT-4o에 넘겨 색·종류·핏을 0~3점으로 채점 → 재정렬 시도
- **결과: 대부분 3점 → 순위 변화 없음.** VLM도 **이미지만으로는** 핏·종류를 구분하지 못함
- **분석**: 문제는 VLM 성능이 아니라 **"이미지라는 정보의 한계"** → 다른 정보원이 필요

### 6-3. 해결 — BGE Reranker (텍스트)
- 이미지로 못 구분하는 핏·종류가 **상품명에는 명시적으로** 존재 (와이드·스트레이트·슬랙스·치노 …)
- `BAAI/bge-reranker-v2-m3` 크로스 인코더로 **검색어 ↔ 상품명 텍스트 관련도**를 채점해 재정렬
- **결과**: 정답(와이드 슬랙스)은 상위로, 오답(스트레이트·치노)은 후순위로 → **핏·종류 모두 개선**
- 리랭킹은 **텍스트 검색에만** 적용 (이미지·멀티모달 검색은 미적용)

## 7. 정량 평가 — VLM-as-Judge

- **평가 셋**: 실제 쇼핑 검색어 **60개** (색상·핏·소재·복합·Hard 6개 유형 — 천장효과 완화)
- **심판**: GPT-4o가 각 결과를 색·종류·핏 기준 **0~3점**으로 판정 (2점 이상 = 관련 상품)
- **편향 회피**: 캡션 생성 모델(Qwen)과 채점 모델(GPT-4o)을 분리 → 자기 채점(순환 편향) 방지
- **측정 지점**: 리랭킹 전 임베딩 검색 결과 → **파인튜닝 자체 효과를 분리 측정**

### 결과 (원본 vs Qwen 캡션 학습 vs 네이버 상품명 학습)

| 지표 | 원본 SigLIP2 | **Qwen 캡션 FT** | 네이버 상품명 FT |
|---|---|---|---|
| nDCG@5 | 0.981 | **0.984** | 0.886 |
| nDCG@10 | 0.969 | **0.977** | 0.844 |
| nDCG@20 | 0.952 | **0.970** | 0.836 |
| 관련 상품 비율(top-20) | 82% | **89%** | 50% |
| 유사도 margin (관련−무관) | +0.012 | **+0.097** | +0.043 |

### 통계적 유의성 — Wilcoxon signed-rank test (Qwen FT vs 원본, 60개 쌍별 nDCG)

| 지표 | 평균 차이 | p-value | 판정 |
|---|---|---|---|
| nDCG@5 | +0.003 | 0.904 | 유의하지 않음 |
| nDCG@10 | +0.008 | 0.597 | 유의하지 않음 |
| nDCG@20 | +0.018 | **0.030** | **유의 (우연 아님)** |

---

## 8. 핵심 발견

- ✅ **Qwen 캡션 파인튜닝 → 개선**: nDCG@20에서 통계적으로 유의(p=0.030), 관련 상품 비율 82→89%, 관련·무관 분리도(margin) 원본 대비 약 8배
- ❌ **네이버 상품명 파인튜닝 → 저하**: nDCG 전 구간 하락, 관련 상품 비율 50%로 붕괴 (노이즈 상품명이 임베딩을 오염)

> **결론: 파인튜닝의 성패는 "어떤 캡션(데이터)으로 학습하느냐"가 좌우한다.** 강한 사전학습 모델에서는 무분별한 파인튜닝이 오히려 성능을 깎을 수 있음을 정량적으로 확인했습니다.
>
> 핏·종류처럼 **이미지 신호로 못 푸는 문제**는, 실패한 접근(VLM 리랭킹)의 원인을 분석한 뒤 **부족한 정보원(상품명 텍스트)** 을 활용해 해결했습니다.

## 12. 회고 & 한계

- 데이터·평가를 **신뢰할 수 있게 설계**하는 것이 모델 성능만큼 중요했다.
- 파인튜닝은 만능이 아니며, **캡션(데이터) 품질**이 성패를 좌우한다.
- 천장(near-ceiling) 지표는 오차감소·유의성 검정으로 엄밀하게 해석해야 한다.
- **한계 & 향후**: GPT-4o 심판도 오차가 있어 사람 라벨 일부 병행 필요, 검증셋(60개) 규모 확대로 유의성 강화 여지.
